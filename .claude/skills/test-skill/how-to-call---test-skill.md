# স্কিল কল করার প্রক্রিয়া (Calling process)

`test-skill` দিয়ে শেখা: এক লাইনে স্কিল কল করে ডাইনামিক প্যারামিটার পাঠানো।

---

## ১. মূল কথা এক লাইনে

```
/স্কিল-নাম  আর্গুমেন্ট১  আর্গুমেন্ট২  ...
```

`/` + স্কিলের নাম লিখে স্পেস দিন, তারপর যা লিখবেন সবই স্কিলের প্যারামিটার। আলাদা করে প্রশ্ন-উত্তরের দরকার নেই।

---

## ২. কল করার ২টি উপায়

| উপায় | কে চালায় | উদাহরণ |
|---|---|---|
| **Slash কমান্ড** | আপনি নিজে | `/test-skill hello 5 fast` |
| **সাধারণ ভাষা** | Claude নিজে বুঝে স্কিল চালায় | "test-skill ব্যবহার করো, title hello, count 5" |

- Slash কমান্ডে আপনি যা লিখবেন হুবহু সেটাই প্যারামিটার হয়। এটাই নিশ্চিত পথ।
- সাধারণ ভাষায় Claude আপনার বাক্য থেকে মান বের করে স্কিলকে দেয়। ভুল বোঝার সুযোগ থাকে।
- `test-skill`-এ `disable-model-invocation: true` আছে। তাই Claude এটা নিজে থেকে চালায় না, শুধু আপনি `/` দিয়ে চালালেই চলে।

---

## ৩. `/test-skill "red box" 5 fast --dry` টাইপ করলে ধাপে ধাপে কী ঘটে

**ধাপ ১: স্কিল চেনা**
`/test-skill` দেখে Claude Code `.claude/skills/test-skill/SKILL.md` খুঁজে পায়।

**ধাপ ২: নামের পরের লেখা আলাদা করা**
বাকি অংশ `"red box" 5 fast --dry` হলো কাঁচা আর্গুমেন্ট স্ট্রিং। এটাই `$ARGUMENTS`।

**ধাপ ৩: ফ্রন্টম্যাটার পড়া**
`SKILL.md`-এর `---` এর ভেতরের সেটিং পড়া হয়:
- `arguments: [title, count, mode]` মানে প্রথম তিনটা আর্গুমেন্টের নাম
- `allowed-tools` মানে কোন কমান্ড বিনা অনুমতিতে চলবে
- `argument-hint` মানে `/` মেনুতে দেখানোর হিন্ট

**ধাপ ৪: আর্গুমেন্ট ভাগ করা (shell-এর মতো কোট নিয়ম)**
স্ট্রিংটা টুকরো হয়:

| অবস্থান | মান |
|---|---|
| `$ARGUMENTS[0]` / `$title` | `red box` (কোটের ভেতরের বাক্য একটাই টুকরো) |
| `$ARGUMENTS[1]` / `$count` | `5` |
| `$ARGUMENTS[2]` / `$mode` | `fast` |
| `$ARGUMENTS[3]` | `--dry` |

**ধাপ ৫: placeholder বদলানো**
`SKILL.md`-এর লেখায় `$ARGUMENTS`, `$title` ইত্যাদি আসল মান দিয়ে বদলে যায়।

**ধাপ ৬: `!`কমান্ড`` চালানো**
স্কিল লোডের সময় ওই কমান্ড চলে এবং আউটপুট লেখার জায়গায় বসে যায় (যেমন আজকের তারিখ, git branch)। Claude কমান্ডটা চালায় না, সে শুধু ফলটা দেখে।

**ধাপ ৭: বিল্ট-ইন ভ্যারিয়েবল**
`${CLAUDE_SKILL_DIR}` (স্কিলের ফোল্ডার) আর `${CLAUDE_SESSION_ID}` (সেশন আইডি) বসে যায়।

**ধাপ ৮: তৈরি টেক্সট Claude-এর কাছে যায়**
সব বদলানোর পর যে চূড়ান্ত লেখা তৈরি হলো, সেটাই Claude-এর কাছে নির্দেশ হয়ে যায়।

**ধাপ ৯: Claude নির্দেশ মেনে কাজ করে**
এখানে Claude নিজে বুদ্ধি খাটায়। `--dry`, `key=value`, URL, JSON চেনা, ডিফল্ট বসানো, ভুল মান ধরা, এসব সিস্টেম করে না, Claude করে। কারণ `SKILL.md`-তে সে নিয়ম লেখা আছে।

---

## ৪. দুই ধরনের প্যারামিটার (এটা বুঝলেই সব পরিষ্কার)

| ধরন | কে সামলায় | উদাহরণ |
|---|---|---|
| **সিস্টেম বদলায়** (ধাপ ৪ থেকে ৭) | Claude Code, Claude দেখার আগেই | `$ARGUMENTS`, `$0`, `$1`, `$title`, `!`cmd``, `${...}` |
| **Claude পার্স করে** (ধাপ ৯) | Claude, নির্দেশ পড়ে | `--dry`, `width=120`, URL, path, JSON, comma list, ডিফল্ট, যাচাই |

সিস্টেম শুধু টেক্সট কেটে বসায়। এর বেশি কিছু বোঝে না। `--dry` যে একটা boolean flag, সেটা বোঝা Claude-এর কাজ। তাই `SKILL.md`-তে স্পষ্ট নিয়ম লিখতে হয়: "`--dry` থাকলে true, না থাকলে false"।

## ৫. কোটিং নিয়ম (সবচেয়ে বেশি ভুল হয় এখানে)

| লিখলেন | কী হলো |
|---|---|
| `/test-skill red box 5` | টুকরো: `red`, `box`, `5` (title হলো শুধু `red`) |
| `/test-skill "red box" 5` | টুকরো: `red box`, `5` (title হলো `red box`) |

**স্পেসওয়ালা মান সবসময় `" "` কোটের ভেতরে দিন।**

## ৬. সব ধরনের কলের উদাহরণ ও কী শেখায়

```
/test-skill hello
/test-skill hello 5 fast
/test-skill "red box" 5 debug
/test-skill hello 5 fast --dry --verbose
/test-skill hello 5 fast width=120 height=80 color=#ff0000
/test-skill hello 5 safe ./docs/PLAN.md /Users/mamun/a.png
/test-skill hello 5 safe https://www.pacdora.com/dielines
/test-skill hello 5 safe red,green,blue 42
/test-skill hello 5 safe {"w":120,"h":80}
/test-skill hello abc turbo
/test-skill
```

| উদাহরণ | কী শেখায় |
|---|---|
| `hello` | শুধু title দিলে বাকিগুলো ডিফল্টে যায় |
| `hello 5 fast` | একই মান positional ও named দুইভাবে পাওয়া যায় |
| `"red box"` | কোটের ভেতরের বাক্য একটাই মান |
| `--dry --verbose` | boolean flag, থাকলে true |
| `width=120 ...` | key=value, Claude একটা map বানায় |
| path ও URL | Claude ধরন চিনে নেয় |
| `red,green,blue 42` | comma list ও সংখ্যা |
| `{"w":120,...}` | JSON, Claude যাচাই করে বৈধ কি না |
| `abc turbo` | ভুল মান, স্কিল কারণ বলে ডিফল্টে চলে |
| শুধু `/test-skill` | title নেই, তাই স্কিল জিজ্ঞেস করে |

## ৭. আপনার আসল সমস্যা: "আবার প্রশ্ন করে কেন?"

কারণ স্কিলের ভেতরে লেখা ছিল "সবসময় নাম জিজ্ঞেস করো"। প্রম্পটে নাম দিলেও সে নির্দেশ মানে।

**সমাধান: নির্দেশে শর্ত লিখুন।**

```markdown
Arguments given by the user: $ARGUMENTS

- If $ARGUMENTS contains a file name, use it. Do NOT ask.
- Only if it is empty, ask the user for the file name.
```

এরপর `/screenshot-to-svg login-form` লিখলে আর প্রশ্ন করবে না। শুধু `/screenshot-to-svg` লিখলে জিজ্ঞেস করবে।

## ৮. নিজের স্কিলে ডাইনামিক প্যারামিটার বানানোর ছাঁচ

```markdown
---
name: my-skill
description: কী করে, কখন চালাতে হয়
argument-hint: "<name> [count] [--flag]"
arguments: [name, count]
---

Raw input: $ARGUMENTS
name = $name, count = $count

Rules:
- name missing -> ask once.
- count missing -> default 3.
- `--flag` present -> true, otherwise false.
```

নিয়ম: প্রতিটা প্যারামিটারের জন্য ৩টা জিনিস লিখুন: **কী**, **ডিফল্ট কী**, **না দিলে কী হবে (জিজ্ঞেস করবে নাকি ডিফল্ট নেবে)**।

## ৯. সাধারণ ভুল ও সতর্কতা

1. **নতুন স্কিল মেনুতে নেই:** সেশন রিস্টার্ট করুন। শুরুর সময় যে ফোল্ডার ছিল না, তা পরে তৈরি করলে ধরা পড়ে না।
2. **`$title` লেখাই থেকে গেছে:** আপনার ভার্সন named arguments সাপোর্ট করে না। তখন শুধু `$ARGUMENTS` রাখুন আর "প্রথম শব্দ = নাম" লিখে দিন।
3. **স্পেসওয়ালা মান ভেঙে গেছে:** কোট ভুলে গেছেন (ভাগ ৫)।
4. **নিরাপত্তা:** ব্যবহারকারীর দেওয়া টেক্সট `!`কমান্ড``-এর ভেতরে সরাসরি বসাবেন না। কেউ `; rm -rf` জাতীয় কিছু ঢুকিয়ে দিতে পারে। `!`...`` শুধু স্থির, নিরীহ কমান্ডের জন্য রাখুন।
5. **`disable-model-invocation`:** `true` দিলে Claude স্কিলটা নিজে চালাবে না। যেসব স্কিলের পার্শ্বপ্রতিক্রিয়া আছে (ফাইল লেখা, ডিপ্লয়) সেগুলোতে দিন।
6. **বর্ণনা (`description`) ভালো লিখুন:** Claude এটা পড়েই ঠিক করে সাধারণ ভাষার অনুরোধে স্কিলটা কখন চালাবে।

---

## ১০. অনুশীলনের ক্রম

1. `/test-skill hello` চালান। দেখুন ডিফল্ট কীভাবে বসে।
2. `/test-skill "red box" 5 fast --dry` চালান। টেবিলে প্রতিটা মানের উৎস মিলিয়ে নিন।
3. `/test-skill hello abc turbo` চালান। ভুল মান কীভাবে ধরা পড়ে দেখুন।
4. শুধু `/test-skill` চালান। দেখুন কখন প্রশ্ন করে।
5. `SKILL.md`-এর নিয়মগুলো একটা একটা বদলে আবার চালান। বদলের প্রভাব সরাসরি দেখতে পাবেন।
